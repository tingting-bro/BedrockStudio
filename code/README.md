# Bedrock Studio · NBT 数据与世界区块编辑器 Demo

Python + FastAPI / React + TypeScript + Vite / pywebview。

设置中的「默认飞行速度」支持 1.6～1024 格/秒，默认 32 格/秒，可输入小数；保存后下次进入 2D / 3D 编辑器时使用。默认值、范围及内部速度倍率基准统一维护于 `backend/src/bedrock_editor/app_constants.json` 的 `flight_speed` 字段，编辑器内仍可临时调整速度。

应用内置常量（包括出厂默认值）统一维护于 `backend/src/bedrock_editor/app_constants.json`：品牌/标题、版本与发布阶段、默认区块视距及范围、地图画质默认值及范围、窗口尺寸、开发端口。前端 `src/lib/constants.ts` 和后端 `constants.py` 从同一文件读取；网页标题、原生标题、API 与安装包版本同步使用这些值。修改后重新构建前端；版本只需修改该 JSON 的 `version`，Python 包版本自动读取，私有前端包不另设版本。快捷键定义仍在前后端各自的 `preferences` 模块中管理；Minecraft 格式常量保留在对应领域模块。

存档工作台支持全部/最近打开筛选、名称/游玩时间排序及封面网格/紧凑列表。存档页、模式选择页和编辑器标题栏均提供「设置」入口：可调整封面、默认地图视图、默认区块视距（4～32 区块，下次进入 2D / 3D 编辑器时使用）、减少动画，并重新绑定保存、NBT 撤销/重做、区块删除、2D/3D 切换、聚焦、工具面板及方块复制/移动/粘贴/取消选区等快捷键。点击按键按钮后直接输入组合键，Esc 取消录入；重复或与窗口/飞行操作冲突的按键不能保存。「恢复默认」需再点击「保存设置」才应用。设置界面的全部用户配置存放于运行工作目录 `settings.json`（快捷键、布局、封面、默认视图、视距、飞行速度及动画偏好）。首次读取时创建文件；若存在旧版 `temp.json` 的 `preferences`，自动复制到新文件，保留旧文件其他内容。已有 `settings.json` 优先，用户配置不会写入源码中的 `app_constants.json`。保存先完整校验并原子替换，失败保留原设置，不修改世界文件。

3D 方块场景与粘贴预览直接使用 Amulet 的模型读取器和 PyMCTranslate：保留真实三角形、逐面 UV、旋转和透明纹理。进入 3D 时检查 Mojang 官方资源版本，首次下载需联网，已有版本复用缓存，更新失败保留可用资源；缓存位于 `运行工作目录/data/render-resources/`。资源下载默认使用镜像：Java 资源依次使用 BMCLAPI 的 `bmclapi2.bangbang93.com`、`bmclapi.bangbang93.com`；基岩版版本列表、资源包/行为包和图标准备工具首次依次使用 `ghproxy.imciel.com`、`gh.catmak.name`、`gh-proxy.org`。连接失败、403、错误网页、文件不完整或校验失败会切换渠道，失败渠道在冷却期内排到最后，其他渠道失败后仍会尝试；读取超时渠道在其他渠道尝试后最多重试一次，校验或 HTTP 拒绝不重试；按本次运行中成功请求的响应时间和吞吐量调整优先级，版本查询与大文件分别记录。大文件请求持续至少 15 秒且平均速度低于 64 KiB/s 时，有备用渠道便切换；连接/单次读取超时为版本查询 8 秒、大文件 10 秒。默认不直连 GitHub/Mojang，也拒绝镜像跳回这些官方站点。镜像服务的节点及跨境回源由其运营方决定，不能保证全链路位于境内。可在启动前通过 `BEDROCK_EDITOR_GITHUB_MIRRORS` 和 `BEDROCK_EDITOR_MOJANG_MIRRORS` 指定逗号分隔的 HTTPS 镜像根地址；GitHub 镜像采用“镜像根地址/原始 HTTPS 地址”形式，Mojang 镜像保留原 URL 路径。仅显式设置 `BEDROCK_EDITOR_ALLOW_ORIGIN_DOWNLOAD=1` 时，才将官方直连作为最后回退渠道。当前按用户要求仅用于个人使用。实体模型与贴图从存档版本对应的资源包生成，并读取渲染控制器及实体行为定义；当前显示静态姿态，动画、自定义 Molang 和部分基岩版专属内容未完整实现；详见 [Amulet 渲染接入](../_references/docs/amulet-rendering-reuse-2026-10-18.md)。

三维选区面板提供「复制区域」，右侧「复制方块实体」「复制实体」默认均勾选，可独立关闭；复制后可「粘贴预览…」，先显示原版贴图的半透明模型和范围框；单击地形表面或修改最小角 X/Y/Z 可调整位置，期间可继续飞行，最后点击「粘贴」才暂存覆盖，取消不修改世界。超过预览预算时显示范围框，实际粘贴仍使用完整剪贴板并执行整批预检。项目内剪贴板属于当前世界会话，包含选区内空气、两层方块存储、原始状态，并按勾选项包含方块实体（含容器物品）及独立实体，不复制待执行事件；支持跨区块、跨维度、重复及重叠粘贴。球形/空心复制只覆盖所选形状，包围盒内其他位置保持原样。容器坐标及双箱关联坐标随位置平移，允许只复制或覆盖部分双箱/门/床；源双箱的另一半未包含在本次粘贴时移除关联，保留箱内物品。可解析但重新序列化字节不同的方块或方块实体不再阻止操作；现代子区块的未知尾随扩展随原区块保留，未修改记录保留原始字节，无法转换的可选实体锚点或方向扩展保留原值。剪贴板是复制时的快照，编辑源区域不会改变它；与编辑历史共享预算，关闭存档后释放。独立实体粘贴分配新身份，重映射本次复制实体间的已知引用，变换位置、朝向和速度，并保留未知 NBT 字段及类型；实体与目标索引同批保存，保留原索引中的其他实体。粘贴沿用暂存、撤销/重做及同步保存流程。未保存的新实体会在场景显示，需保存后编辑其 NBT；「移动方块选区」仅移动方块及所选方块实体，独立实体留在原处。完整读取并校验的现代区块允许省略全空气子区块，复制时保留其空气语义，填充/粘贴时仅按实际变化创建 v9 子区块；填充／粘贴遇到未生成的目标区块时自动新增空区块，与本次编辑一起暂存、撤销／重做和保存；标准维度使用默认高度，自定义维度按选区高度对齐完整子区块。复制选区内未生成或暂存删除的区块按空气处理，不包含原有方块实体；读取失败及损坏数据整批拒绝，自动创建同样受共享预算及完整预检约束。

未知方块不再阻止覆盖、按名称替换、复制和粘贴；复制保留原始 NBT 类型、根名称及扩展字段，旋转或镜像时未知方向状态原样保留。同一未知方块可编辑已有状态。旧地形及待执行事件记录不再阻止现代子区块操作，未参与编辑的记录保持原始字节；剪贴板不复制事件。仅含旧地形而缺少现代子区块的位置暂按空气复制，覆盖时按需创建现代子区块；这不代表已实现旧地形格式转换。损坏的现代子区块、预算超限及冲突仍在整批预检时拒绝。

玩家和玩家重生点打开同一现有玩家 NBT 记录，支持标签编辑；玩家图标可以删除整条玩家记录，重生点图标不提供整体删除。传送门图标只编辑/删除 PortalRecords 对应条目，保留其他条目和未知字段。地图中心和常加载区域打开对应 map_* / tickingarea_* 记录；村庄打开 VILLAGE_*_INFO，删除只移除此 INFO，保留 POI、DWELLERS 等关联记录和地形。这些命名记录复用原编辑历史、保存点与数据库批次，地图「还原」也清除其未保存修改。缺少有效位置或维度的记录不猜测坐标；字段与研究来源见 [地图对象图层研究](../_references/docs/map-object-layers.md)。

单独删除独立实体会同步清理全部 digp 引用和同坐标的迁移旧实体副本，保留其他对象；整区块删除继续遵循既有范围，保留独立 actorprefix/digp。对象修改、删除和索引清理完整预检后暂存，与普通 NBT 和区块操作共用 64 MB 预算及一次同步数据库 batch，保存前再次检查源记录指纹，不创建数据库备份。地图「还原」清除所有未保存对象修改/删除及区块操作；已保存的对象整体删除不提供地图恢复。区块删除与同坐标未保存对象 NBT 冲突时拒绝，需先保存或还原。关闭时「保存并关闭」先校验并提交未确认的标签输入，失败保留面板和草稿。

## NBT 数据编辑

启动后先选择世界，再进入两栏 NBT 编辑器：左侧世界文件树包含 `level.dat`、`players` 和 `data`；players 下方依次列出同级 Maps、Tickingareas、Structures、Portals、scoreboard 和 data；data 显示其余命名 NBT。右侧按左侧选择显示目录、记录列表、地图卡片或当前记录的 NBT 树。选择世界根时，右侧显示与左栏顺序、图标和右键操作一致的八个目录入口，点击分类或搜索后才加载记录。自动发现当前用户的国际基岩版、Preview 和旧版 UWP 存档目录；扫描 `Users/*`，不固定用户名或游戏账号 ID。「其他存档」支持原生文件夹选择器。

### 编译与安装包

根目录 `build.py` 使用 Nuitka 将 Python 代码编译为原生程序，再用 Inno Setup 6
生成 Windows x64 安装包。采用 standalone 编译分发，随包携带 Python 运行库、
Node.js、数据库原生驱动及前端资源；目标电脑无需安装 Python 或 Node.js。
这不是所有依赖都静态链接的单文件程序，仍包含 DLL，并需要系统安装
Microsoft Edge WebView2 Runtime 和 .NET Framework 4.7.2+。安装程序会检查 WebView2。

构建电脑需要 Windows x64、64 位 Python 3.12+、x64 Node.js 20.19+ 和
Inno Setup 6。C 编译器优先使用已有的 Visual Studio Build Tools；没有时
Nuitka 按其支持情况下载编译工具。首次准备和打包，在项目根目录执行：

```powershell
python -m pip install -e "./code[build]"
python build.py --check
python build.py
```

可用 `--iscc "C:\Program Files (x86)\Inno Setup 6\ISCC.exe"` 指定安装器编译器，
`--jobs 4` 控制 C 编译并发数。缺少前端依赖时自动运行 `npm ci`，已有依赖直接复用，
不会默认重新下载资源。默认清理旧发布产物，保留 `build/native/start.build/` 的 C 编译缓存
和 `build/.cache/` 的 TypeScript 检查缓存；前端构建与原生编译同时执行，全部通过后才组装安装包。
每次仍由 Nuitka/SCons 检查源码和编译依赖，不直接复用旧可执行文件。
`--clean` 删除整个 `build/` 后全新构建。拒绝清理被链接或重定向到其他位置的目录；
`--help` 和 `--check` 不会清理产物。

打包名称与信息统一读取 `backend/src/bedrock_editor/app_constants.json`。顶层 `brand`、`edition`、`caption`、`description`、`version`、`channel` 用于产品名、描述、版本及发布阶段；`packaging` 管理可执行文件名（`executable_name`，不含扩展名）、发布者（`publisher`）、安装标识（`app_id`）、安装目录（`install_directory`）、用户运行目录（`state_directory`）和安装包名称模板（`installer_name`，不含扩展名）。模板支持 `{executable_name}`、`{channel}`、`{version}`。同一份配置用于 EXE 版本资源、安装器信息、快捷方式、卸载图标与最终文件检查；配置错误会在清理旧产物前拒绝构建。安装标识和目录沿用原有值，保持升级识别与用户配置位置；修改展示名或版本时无需改动它们。

前端产物、Nuitka 中间文件、编译报告、安装器脚本及最终
`<程序名>-<阶段>-<版本>-windows-x64-setup.exe`（可由模板调整）全部写入 `build/`。
构建失败返回非零退出码，依赖检查失败保留旧产物；开始构建后失败则保留本次中间文件。
安装包按当前用户安装，创建开始菜单入口，可选桌面快捷方式。
快捷方式的工作目录为 `%LOCALAPPDATA%\Bedrock Studio`，用于保存 `settings.json`、`temp.json`

## 使用

1. 选择页优先显示最近成功打开的存档，按打开顺序保存最多 20 个（包含「其他存档」），与本地扫描结果去重。点击存档卡片，「打开存档」变为可点击；损坏的文件会显示原因并禁用。
2. 「其他存档」选择包含 `level.dat` 的世界文件夹。浏览器模式还可以输入文件夹路径。
3. 选择左侧 `players`，右侧显示玩家列表；顶部筛选名称或键 ID 文本，每页 200 条并使用虚拟滚动，单击选择 `~local_player` 或其他玩家记录，双击或按 Enter 进入 NBT 树编辑。左栏只显示当前玩家，避免长列表挤占导航。切换 `level.dat` / 玩家时保留未保存修改，各记录分别撤销/重做；玩家记录可右键删除；在 players 根右键「新增玩家记录」输入完整键名称，创建后进入 NBT 编辑。支持新增，不提供重命名记录键。

   左侧 players 下方依次放置同级 Maps、Tickingareas、Structures、Portals、scoreboard 和 data。选择 `data` 显示其余命名 NBT，包括 AutonomousEntities、BiomeData、Nether、Overworld、TheEnd、mobevents、schedulerWT、VILLAGE 等；五个常用入口不会重复出现在 data 列表中。长列表显示在右侧。scoreboard 入口显示准确键 scoreboard 的记录；未存在时显示空列表，不提供任意创建该键。名称按字符长度升序，同长度按 A～Z 排列（忽略大小写）。全部列表每页 200 条，支持筛选、多选、右键和双击进入 NBT。Maps 用地图图片卡片显示，每页 24 条；单击选中，双击或按 Enter 进入详细 NBT，Space 选择卡片。地图预览包含透明度，并读取未保存的颜色修改；没有有效颜色数据时显示占位，仍可尝试进入 NBT。Tickingareas、Structures、Portals 用分页虚拟列表显示，每页 200 条，单击选择、双击或按 Enter 进入 NBT。分类列表均可筛选名称或键 ID，不将全部记录展开到左栏。左右两侧分类根右键可新增记录，世界/data 根提供分类子菜单；已有 Portals 时禁止重复新增。level.dat 或具体记录在左栏右键也可直接新增根下标签。
4. 右侧玩家列表和左侧当前玩家可右键删除整条记录。右键 players 根删除全部玩家，包含筛选和分页之外的玩家；右键 level.dat 根或 NBT 根删除全部子标签；右键世界根清空 level.dat 标签并删除全部玩家。菜单和确认框明确范围，保留文件、数据库、区块和其他世界数据。确认仅修改内存，点击保存时写入。

   data 的卡片、列表行及左侧当前记录同样可以右键删除整条记录；右键 data 删除其余命名 NBT（保留五个常用入口），右键常用分类根删除对应分类下全部记录，不限筛选和分页。操作可在列表范围撤销/重做。世界根仍保留 data，清空范围以确认框为准。

   玩家列表、全部 data 列表/卡片支持多选：Ctrl/Meta 点选增减、Shift 连选当前页范围、Ctrl/Meta+Shift 连选并保留其他选择；Ctrl/Meta+A 选择当前筛选的全部分页，Esc 清空选择。翻页保留已选 ID，筛选、切换分类或发生修改后清空，底部显示已选数量。右键已选项保留整组；右键未选项则只选该项。菜单中的删除作用于全部选中记录，新增标签用一份名称、类型和值分别写入所有选中记录的根节点。

5. 搜索范围随左侧选择变化：选世界名称时查找 level.dat、全部玩家和 data NBT（含未保存修改），结果注明所属记录，双击进入并定位标签；选 data 时筛选其余命名 NBT 记录的名称或键 ID；选具体记录时查找该记录的名称、路径或值；选 players 或 data 分类时筛选名称或键 ID。切换范围清空搜索。完成编辑弹窗后点击「保存存档」，保存所有已修改的记录。`level.dat` 修改生成 `level.dat.bak.时间戳-编号`，玩家/data 修改使用单次同步批次写入，不创建 `db.bak.*` 或 `.partial` 数据库备份目录。
6. `Ctrl+S` 保存；在输入框以外，`Ctrl+Z` / `Ctrl+Shift+Z` 撤销/重做。players / data 分类 / 世界列表范围撤销新增记录、整条记录删除、批量新增标签与世界清空（最多 50 次），记录范围撤销标签编辑。已保存的删除也可在保留的历史内撤销，再保存恢复已知数据库键。若关联记录后来已修改，须先撤销后续修改，避免覆盖新内容。
7. 点击窗口「×」显示关闭确认。有修改时可选择「保存并关闭」「不保存」「取消」。尚未提交的标签输入也会在保存时先校验和应用；保存失败会保留窗口及修改。

最近记录保存在 运行工作目录（`Path.cwd()`）下的 `temp.json`，重启程序后保留，不更改世界文件；不存在的路径不显示。只有成功打开才更新最近顺序。历史文件损坏或无法写入时显示错误，仍可正常打开存档。测试用 `BEDROCK_EDITOR_STATE_DIR` 隔离历史目录。

## Demo 范围

- NBT 数据模式编辑基岩版 `level.dat` 和世界 LevelDB 中现有的 `~local_player`、`~local_player.Editor`、`player_*`、数字 ID 的 `map_*`、`tickingarea_*`、`structuretemplate_*` 和准确键 `portals` / `scoreboard`，以及其他具有小端 Compound 头的命名 NBT 记录。其他命名 NBT 支持编辑和删除，但不开放任意新建键。数据库记录采用无文件头的小端 NBT，键用十六进制 ID 定位。允许编辑、删除、恢复已枚举的支持键和新增经过分类校验的键，不提供重命名或任意数据库键，也不自动创建数据库。区块及地图对象操作位于世界区块模式，范围见本文开头。
- 新记录名称按分类验证：玩家 `~local_player` / `~local_player.Editor` / `player_` 非空后缀；地图 `map_` 后跟规范的 64 位有符号整数（不含前导零或负零）；区域 `tickingarea_` 非空后缀；结构 `structuretemplate_` 非空后缀；传送门准确键 `portals`。禁止控制字符，最多 512 个 UTF-8 字节。普通新记录为空 Compound，地图带 mapId、128×128 尺寸和透明 RGBA colors 基础标签，后续由用户补充 NBT，并非完整游戏数据模板。新增记录先暂存，保存时校验该键仍不存在，直接批次写入；重复键、当前会话的已删除键不能同名创建（可撤销/重做恢复）。新增草稿纳入关闭确认，保存并关闭先校验并创建。
- 支持全部 12 种 NBT 类型的新增、删除、标量值修改、Compound 子标签重命名，以及 List/数组元素编辑。Compound 使用名称；List/数组追加元素时自动分配索引，并限制元素类型。新 List 可选择元素类型；数组可整体编辑，整数用逗号、空格或换行分隔。
- 支持搜索、按需展开与分页、虚拟树列表、level.dat 备份保存和每条记录最多 50 次撤销（整个世界会话共享 64 MB 快照预算）。编辑后保留已展开的容器和滚动位置；删除后选中下一个同级节点，末尾选中前一个，同级已空则选中父节点。
- 保留 NBT 标签类型、未知字段、根名称、文件头版本；重算文件头长度。Long 通过 API 使用字符串，避免 JavaScript 精度损失。
- 暂不支持直接变更已有标签类型、SNBT 视图或发布为独立 exe。编辑页包含 `level.dat`、`players`、data 其他命名 NBT 列表及五个常用入口，不显示二进制区块键或日期面板。
- level.dat 和每条数据库 NBT 最多 16 MB。单记录及世界/data 搜索最多遍历 25,000 节点并返回 500 条，包括数组元素；世界/data 搜索另限 1,000 条记录或累计 64 MB 记录数据，20 条读取错误后停止；到达上限提示截断。无法读取的记录或数据库会显示错误，同时保留已经找到的其他结果。范围搜索不会把所有记录加入编辑历史缓存。
- 返回选择页时关闭文档；列表索引和名称作为本 demo 的节点定位，重命名后自动选中新节点。
- 地图预览直接从 RGBA 字节生成 PNG，无额外图片依赖；默认尺寸 128 × 128，支持有效整数尺寸到 1024 × 1024，并严格核对颜色数量。预览不加载编辑历史，图片请求校验本地会话令牌和 revision，切换或刷新时释放图片资源。

## 玩家与 data 保存和恢复

数据库保存直接使用单次同步 batch 写入玩家/data 的新增、编辑、删除及撤销恢复，不生成 `db.bak.*` 或 `.partial` 备份目录，也不复制整个数据库。保存前校验 NBT 和外部记录指纹；恢复已删除键要求该键仍不存在，禁止覆盖外部数据。写入失败保留未保存状态和撤销历史。已有备份目录不会自动删除。`level.dat` 仍保留原有备份逻辑。
